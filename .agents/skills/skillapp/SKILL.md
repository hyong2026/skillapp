# 操作 SkillApp

三个步骤。**本文件只回答「这一步该做什么」**，不复制各命令的选项——那些用 `-h` 查，免得维护第二份真相。

| # | 步骤 | 用户给什么 | 用户得到什么 |
|---|---|---|---|
| 1 | **装载** | 一个 Skill 路径 | 复制进 SkillApp + 一份**分析报告**（供评审）|
| 2 | **映射** | 一个飞书表格链接 | 表格列 + Template |
| 3 | **执行** | —— | 回写的结果 |

**闸门在「装载 → 映射」之间。** 装载只产出报告，不碰表格；映射会改表格结构，先把报告交给用户评审。用户未回复不会阻塞后续操作；真正进入映射时，按报告里的默认建议执行。

**一次只做一步。** 用户说「装载」就只装载（复制 + 分析），做完交报告并停下；**不要顺手往下推**。可以提议下一步，但别自己走进去。

## 1 装载

这一步包含两个动作：

1. **复制进来并固定版本** —— `node bin/load-skill.js <源目录> --ref <name>`
2. **分析它的输入输出** —— 用 `analyze-skill-io`

上游改动后**必须重新装载**才生效——它会覆盖 `skills/<ref>/` 并重算内容指纹。指纹一变，旧 Template 就被执行器拒绝；这是故意的，在逼人复核映射。

`--ref` 是装载后的名字，也是 Template 里 `skill.path` 的末段。

**交付物是分析报告**（契约草案 + 风险清单），到此停下，等用户评审。待确认项必须给出建议、依据和不回复时采用的默认；用户未回复即采纳建议。

## 2 映射

只在两种情况需要重跑：Skill 的 IO 变了，或表格结构变了。**它会改用户表格的结构**，所以只在该做的时候做。

跑之前确认分析报告已交付给用户，且**风险清单**的待确认项已有明确答复或默认建议可执行。

```bash
node bin/map-table.js --ref <ref> --url '<表格链接>'
```

契约默认读 `tmp/<ref>.io-schema.json`（由 `--ref` 推导），不用手写路径。

## 3 执行

**默认 `--pending`**：只跑「工作版本或输入与最近一次成功运行不一致」的行；Skill、Mapping、目标或输入变了都会重跑，重复执行安全。

`--all` 会无视历史重跑全表，只在用户明确要求时用。行数多时先 `--dry-run` 看一眼解析出的命令。

## 清空 / 重来

```bash
node bin/unload-skill.js <ref>          # 卸载一个 Skill 和引用它的 Template
node bin/unload-skill.js --all --yes    # 清空整个内容层（引擎保留）
```

本地能清干净，**飞书表格里的列不会被删**——脚本不碰用户的表；要去掉得在表格里手工删，或换一张表。

运行记录默认保留（卸载再重装时 `--pending` 的历史才不白攒）；要一起删就加 `--with-runs`。

## 状态在哪

| | |
|---|---|
| 运行记录（Run / RunItem） | `runs/<run_id>/run.json` |
| 多维表格 | **只有输入列和输出列**，不含任何运行状态 |

失败的行会被 `--pending` 一直捞出（它就是「最近一次没成功」）。要让某行退出待运行，只能修输入，或用 `--record-id` 单独跑别的行。
